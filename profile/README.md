<h2>四个 IP 到手先做一件事：把用途写下来</h2>
<p>拿到一条带四个地址的专线，第一反应往往是先全都配上试试。更有效的顺序是先定用途：哪个地址给主业务、哪个给备用、哪个给测试、哪个留空。用途定了，配置方法自然就定了，也不会出现四个地址全混着用的情况。</p>
<p>这条专线的四个地址通常在同一段内，共享链路带宽。这意味着它们的速度表现基本一致，差别只在对外呈现。所以分配的真正意义是「区分身份」，不是「区分性能」。</p>

<h2>地址绑在哪一层，决定了后面好不好管</h2>
<p>常见的三个层次：绑在服务器的网卡上、绑在路由器的广域网口上、绑在网关的策略规则里。绑网卡是设备直接持有地址，配置直观；绑路由器是线路侧持有，内网设备共享；绑策略是灵活但需要一个能按规则分流的网关。</p>
<p>如果只有一台服务器要用四个地址，直接绑网卡最简单。如果多台设备要分别用不同地址，绑在网关侧统一分流更好管。先按使用规模选层次，别按习惯选。</p>

<h2>路由器上的配置要点</h2>
<p>路由器侧要处理三件事：把四个地址都配到外网接口上、确认回程路由正确、设置源地址选择规则。前两件是基础，第三件决定「谁走哪个地址」。如果路由器不支持源地址策略，就得靠内网设备自己指定，管理成本会上升。</p>
<p>配置完成后一定要在路由器上直接测一遍：从每个源地址分别访问外部，确认出口地址与预期一致。只在服务器上测是不够的，因为中间可能有一层地址转换把源地址改掉了。</p>

<h2>服务器上的配置要点</h2>
<p>服务器侧要确认地址真的绑在网卡上、能对外通信、并且程序能指定使用哪个地址出网。第三点最容易被忽略——很多程序默认用系统选择的主地址，就算绑了四个，实际出网的还是同一个。</p>
<p>解决办法有两种：让程序支持指定源地址，或者用策略路由按目标或按用户分流。前者改动小，后者通用性强。先看程序是否支持，不支持再上策略路由。</p>

<h2>地址分配好之后，怎么验证配置真的生效</h2>
<p>验证要看「实际出网地址」，不是看配置文件。从每个使用方分别发起一次访问，查询对方看到的源地址，与预期比对。四组数据全部对上，才算配置完成。</p>
<p>建议同时验证一下反向的情况：当主地址不可用时，备用地址能不能顺利接上。这一步在多账号场景里价值很高，因为故障切换如果没验证过，真出事时大概率接不上。</p>

<h2>三个常见配置错误</h2>
<p>第一个是地址配上但没配路由，表现是能 ping 通自己、出不去。第二个是配了地址但程序不用，表现是四个地址只有一个在出网。第三个是策略规则写反了，表现是原本该走 A 的流量走了 B，很难从日志看出来。</p>
<p>这三个错误的共同点是「配置看起来对、行为不对」。所以判断标准只能是实测出网地址，不能是配置文件内容。</p>

<h2>四个地址够不够，怎么判断</h2>
<p>看两件事：需要区分的身份有几组、每组的变化频率有多高。身份组数直接决定最少要几个地址；变化频率决定要不要留余量。一个常用的经验是留一个空位作为周转，用于替换或临时验证。</p>
<p>如果发现四个地址不够，别急着在一条线路上硬塞更多，先评估是不是该增加线路。同一条线路上的地址再多，也共享同一份链路质量和同一个故障域。</p>

<h2>常见问答</h2>
<h3>四个地址可以只用一个吗？</h3>
<p><strong>答：</strong>可以，但浪费了资源，也失去了分散身份的能力。至少把测试和主业务分开。</p>
<h3>同一台服务器能同时从四个地址出网吗？</h3>
<p><strong>答：</strong>能，但需要程序支持指定源地址或配置策略路由，默认行为通常只用主地址。</p>
<h3>地址段相同会不会被一起识别？</h3>
<p><strong>答：</strong>同段地址在外部看关联度较高，这一点无法通过配置改变，只能在分配策略上接受或规避。</p>
<h3>配置改完需要重启吗？</h3>
<p><strong>答：</strong>视操作系统与网络管理方式而定，多数需要重新加载网络配置。重启前先确认备用访问方式可用，避免把自己锁在外面。</p>
